# 아라아띠 포팅 매뉴얼 — 빌드 · 배포

C101 팀 · 아라아띠 (바닷속 협동 멀티플레이 게임)

GitLab 저장소를 받은 뒤 **빌드하고 EC2 에 배포하기까지** 필요한 내용을 정리했습니다.
서버가 없다면 **6장(새 EC2 에 처음부터 구축하기)** 부터, 이미 구축된 서버라면 **7장** 부터 보면 됩니다.
외부 서비스는 [02_외부서비스.md](02_외부서비스.md), DB 덤프는 [03_araatti_dump.sql](03_araatti_dump.sql), 시연 순서는 [04_시연시나리오.md](04_시연시나리오.md) 에 있습니다.

## 4. 빌드

### 4-1. 게임 — 게임 서버 4종 + 클라이언트 (Windows, PowerShell)

```powershell
# Unity 를 닫은 상태에서. 리눅스 서버 4종 → 윈도우 Release 클라이언트 순서로 굽는다 (약 5분)
powershell -ExecutionPolicy Bypass -File tools\deploy\build-release.ps1

# 클라이언트 + 실행 배치(게임시작.bat) + 안내문 + 완드 드라이버 → zip
powershell -ExecutionPolicy Bypass -File tools\deploy\pack-client.ps1
```

| 결과물 | 위치 |
|---|---|
| 게임 서버 4종 | `unity/UnderTheSea/Builds/Linux/{Server, MineServer, WarriorsServer, ShipCoopServer}` |
| 클라이언트 | `unity/UnderTheSea/Builds/Showcase/AraAtti-Flow.exe` |
| 배포 zip | `unity/UnderTheSea/Builds/AraAtti-EC2.zip` (약 460MB) |

- `build-release.ps1` 은 Unity 를 배치 모드로 **순서대로** 띄웁니다(한 프로젝트를 두 Unity 가 동시에 못 연다). 에디터가 열려 있으면 실패합니다.
- Unity 경로는 `C:\Program Files\Unity\Hub\Editor\6000.5.9f1\Editor\Unity.exe` 로 적혀 있습니다. 다르면 스크립트 첫 줄을 고칩니다.

### 4-2. 계정 API

```bash
dotnet publish server/AraAtti.Api/AraAtti.Api.csproj -c Release -r linux-x64 --self-contained false -o <폴더>
tar -czf api.tar.gz -C <폴더> .
```

⚠ `--self-contained false` 여야 합니다. SDK 10 으로 net8.0 을 self-contained 로 굽으면 프레임워크 DLL 이 빠진 채 나와 EC2 에서 켜지지 않습니다. EC2 에는 `aspnetcore-runtime-8.0` 이 깔려 있습니다.

## 6. 새 EC2 에 처음부터 구축하기

지금 운영 중인 EC2(43.202.67.137)가 없다고 가정하고, **빈 Ubuntu 서버 한 대**에 전체를 세우는 순서입니다.
명령은 지금 EC2 에 실제로 깔린 구성(Ubuntu 기본 저장소 패키지)을 그대로 따릅니다. 30~40분 걸립니다.

### 6-1. 서버 준비

| 항목 | 값 |
|---|---|
| OS | **Ubuntu 24.04 LTS** (x86_64) |
| 사양 | 권장 **vCPU 4 · RAM 16GB** (지금 t3.xlarge). 게임 서버 7대 + API + MySQL 이 모두 합쳐 메모리 약 3GB, 접속자 0명일 때 CPU 1코어 안팎 |
| 디스크 | 30GB 이상 (빌드 · 백업 · zip) |
| 공인 IP | **고정 IP**(탄력적 IP)를 쓴다. 바뀌면 7단계의 두 곳을 고치고 클라이언트를 다시 빌드해야 한다 |

**방화벽** — 클라우드 보안 그룹과 서버 UFW **둘 다** 연다.

| 포트 | 용도 |
|---|---|
| 22/tcp | SSH |
| 80, 443/tcp | 홈페이지 · 클라이언트 다운로드 (nginx) |
| 5080/tcp | 계정 API |
| 27015~27021/udp | 게임 서버 7대 |

⚠ 3306(MySQL)은 열지 않습니다. MySQL 은 서버 안(127.0.0.1)에서만 씁니다.

### 6-2. 패키지 설치

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2 aspnetcore-runtime-8.0 nginx tcpdump unzip
sudo apt install -y certbot python3-certbot-nginx     # 도메인 + HTTPS 를 쓸 때만

sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw allow 5080/tcp && sudo ufw allow 27015:27021/udp
sudo ufw enable

mkdir -p ~/araatti/staging ~/araatti/server
```

설치 확인 — 지금 EC2 기준 버전:

| 명령 | 지금 EC2 |
|---|---|
| `docker --version` | 29.1.3 |
| `docker compose version` | 2.40.3 |
| `dotnet --list-runtimes` | Microsoft.AspNetCore.App 8.0.31 |
| `nginx -v` | 1.24.0 |

### 6-3. MySQL (Docker)

저장소의 `server/docker-compose.yml` 을 그대로 씁니다.

```bash
# 내 PC 에서
scp -i <키.pem> server/docker-compose.yml server/.env.example ubuntu@<서버IP>:~/araatti/server/

# 서버에서
cd ~/araatti/server
cp .env.example .env
nano .env        # MYSQL_ROOT_PASSWORD 와 MYSQL_PASSWORD 를 정해서 적는다 (change-me 그대로 두지 않는다)
sudo docker compose up -d
sudo docker compose ps          # STATUS 가 (healthy) 가 될 때까지 20~30초 기다린다
```

- 컨테이너 이름은 `araatti-mysql`, 재시작 정책은 `unless-stopped` 라 **서버를 재부팅해도 MySQL 은 다시 켜집니다.**
- `MYSQL_BIND` 를 비워 두면 127.0.0.1 에만 열립니다. 바꾸지 않습니다.

**데이터 넣기** — 둘 중 하나.

```bash
# A. 이 문서의 덤프를 복원 (표 + 시연 데이터 + 마이그레이션 기록. 계정은 user{번호}@example.com / araatti1234!)
scp -i <키.pem> exec/03_araatti_dump.sql ubuntu@<서버IP>:~/araatti/
sudo docker exec -i -e MYSQL_PWD='<MYSQL_PASSWORD>' araatti-mysql \
  mysql -h 127.0.0.1 -u araatti araatti < ~/araatti/03_araatti_dump.sql

# B. 빈 DB 로 시작 — 내 PC 에서 스키마 SQL 을 만들어 올린 뒤 같은 방법으로 넣는다
cd server && dotnet tool restore
dotnet ef migrations script --idempotent --project AraAtti.Api -o schema.sql
```

B 로 시작해도 제단 행(`altar_state`, 목표 1000)은 마이그레이션이 만들어 줍니다. 시연처럼 목표를 100 으로 쓰려면
`UPDATE altar_state SET target_offering = 100 WHERE id = 1;` 을 한 번 실행합니다.

확인:

```bash
sudo docker exec -e MYSQL_PWD='<MYSQL_PASSWORD>' araatti-mysql \
  mysql -h 127.0.0.1 -u araatti araatti -e "SHOW TABLES; SELECT * FROM __EFMigrationsHistory;"
```

`__EFMigrationsHistory` 에 `InitialCreate` 와 `AddInventoryAndAltar` 두 줄이 보여야 합니다.

### 6-4. 계정 API 설정 — `~/araatti/api.env`

```bash
openssl rand -base64 48          # JWT 서명 키로 쓸 값을 하나 만든다
```

- Gemini 키가 없어도 API 는 켜집니다. 광산 한 줄 평만 고정 문구가 됩니다.

### 6-5. 서버 IP 를 바꾸고 빌드 · 첫 배포

IP 가 다르면 **세 파일**을 고칩니다. 앞의 두 개를 고친 뒤 4장대로 빌드합니다(클라이언트가 이 주소를 안고 구워진다).

| 파일 | 고칠 곳 |
|---|---|
| `tools/deploy/deploy-servers.sh` | `PUBLIC_IP=<서버IP>` — 게임 서버의 `-publicip` |
| `tools/deploy/pack-client.ps1` | `$Server = '<서버IP>'` — `게임시작.bat` 의 API 주소 |
| `web/scripts/deploy.mjs` | `const HOST = 'ubuntu@<서버IP>'` — 홈페이지 배포 대상 (6-6) |

```powershell
# 내 PC 에서 (4장)
powershell -ExecutionPolicy Bypass -File tools\deploy\build-release.ps1
powershell -ExecutionPolicy Bypass -File tools\deploy\pack-client.ps1
dotnet publish server/AraAtti.Api/AraAtti.Api.csproj -c Release -r linux-x64 --self-contained false -o api-out
```

```bash
# 내 PC 에서 — 올리기
cd unity/UnderTheSea/Builds/Linux
tar -czf servers.tar.gz --exclude="*_BurstDebugInformation_DoNotShip" Server MineServer WarriorsServer ShipCoopServer
tar -czf api.tar.gz -C <api-out 경로> .
```


### 6-6. 홈페이지와 다운로드 (nginx)

```bash
sudo mkdir -p /var/www/araatti
sudo mv ~/araatti/staging/AraAtti.zip /var/www/araatti/AraAtti.zip
sudo chown -R www-data:www-data /var/www/araatti
sudo nano /etc/nginx/sites-available/araatti.conf
```

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;                       # 도메인이 있으면 araatti.site www.araatti.site

    root /var/www/araatti;
    index index.html;
    charset utf-8;
    sendfile on;
    tcp_nopush on;

    location / {
        try_files $uri $uri/ =404;
    }

    location = /AraAtti.zip {
        add_header Content-Disposition 'attachment; filename="AraAtti.zip"';
        add_header Cache-Control "public, max-age=3600";
    }

    access_log /var/log/nginx/araatti.access.log;
    error_log  /var/log/nginx/araatti.error.log;
}
```

```bash
sudo ln -sf /etc/nginx/sites-available/araatti.conf /etc/nginx/sites-enabled/araatti.conf
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# 홈페이지 올리기 — 내 PC 에서. web/scripts/deploy.mjs 의 HOST 를 새 IP 로 바꾼 뒤(6-5)
cd web && npm install && npm run deploy
```

**도메인 + HTTPS (선택)** — DNS A 레코드를 새 IP 로 돌린 뒤:

```bash
sudo certbot --nginx -d araatti.site -d www.araatti.site      # 443 설정과 80 → 443 넘기기를 알아서 넣는다
sudo certbot renew --dry-run                                   # 자동 갱신 확인
```

도메인이 없으면 `http://<서버IP>/` 로 홈페이지와 `http://<서버IP>/AraAtti.zip` 다운로드가 됩니다.

### 6-7. 접속 확인

1. 다른 PC 에서 `http://<서버IP>/AraAtti.zip`(또는 도메인)을 받아 풀고 **`게임시작.bat`** 실행
2. [회원가입] → 캐릭터 만들기 → 채널 입장 → 로비에서 다른 PC 캐릭터가 보이는지
3. 포탈 `F` → 인원 선택 → 미니게임 서버로 넘어갔다가 결과 판 [로비로] 로 돌아오는지
4. 안 붙으면: 보안 그룹 UDP 27015~27021 · `-publicip` 값 · 클라이언트와 서버가 **같은 빌드**인지 확인

### 6-8. 재부팅했을 때

- MySQL 은 Docker 가 다시 켭니다.
- **게임 서버 7대와 API 는 다시 켜지지 않습니다**(systemd 미등록, `nohup` 으로 실행). 서버에 들어가
  `cd ~/araatti && ./deploy-servers.sh` 를 실행하면 됩니다. `staging/` 에 마지막으로 올린 빌드가 남아 있어 같은 빌드로 다시 뜹니다.

## 8. 배포 시 특이사항

- **서버와 클라이언트는 한 벌로 올린다.** 네트워크 코드가 다른 빌드끼리는 `Behaviour count mismatch` 로 접속이 깨진다. 클라이언트 전용 변경(화면 · 영상)만 zip 만 올려도 된다.
- **접속자가 있을 때 배포하지 않는다.** `deploy-servers.sh` 는 게임 서버 7대를 모두 재시작한다(API 만 바꿔도 그렇다).
- **`-publicip` 이 없으면 아무도 못 붙는다.** 포트도 열려 있고 로그도 멀쩡해서 원인을 찾기 어렵다.
- **`.bat` 은 CRLF + CP949, `.ps1` 은 UTF-8 BOM** 으로 쓴다. 아니면 cmd 가 `set` 을 못 읽거나 PowerShell 5.1 이 한글을 깨뜨린다. `pack-client.ps1` 이 알아서 맞춘다.
- **`appsettings.Development.json` 은 배포본에 넣지 않는다.** 개인 DB 비밀번호 · JWT 키가 들어 있다. `.csproj` 의 `CopyToPublishDirectory="Never"` 와 `deploy-servers.sh` 가 이중으로 막는다.
- **systemd 등록이 없다.** `nohup` 으로 띄우므로 EC2 가 재부팅되면 `deploy-servers.sh` 를 다시 실행해야 한다.
- **완드 드라이버**: 배포 zip 의 `WandDriver\` 에 CP210x 드라이버가 있다. `게임시작.bat` 이 동글이 꽂혀 있고 드라이버가 없을 때만 관리자 확인 창을 한 번 띄워 설치한다(키보드만 쓰는 PC 는 묻지 않는다).
  ⚠ 드라이버 파일은 한 바이트도 바꾸면 안 된다(서명 `silabser.cat` 이 `silabser.inf` 의 해시). `.gitattributes` 에서 `tools/deploy/drivers/** -text` 로 줄바꿈 변환을 막았다.
- **SSAFY EC2 주의**: `shutdown` · `poweroff` 금지(다시 켤 수 없음), SSH 포트 차단 · 공개키 삭제 · `/home` 권한 변경 금지(복구 불가, 초기화만 가능). MySQL 컨테이너 · 볼륨은 지우지 않는다.
