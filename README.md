# SSAFY 7주 프로젝트 아이디어 1차 기획안

게임과 IoT를 결합하여, **일반적인 키보드·마우스 입력을 넘어 실제 신체 움직임이나 장치를 게임 플레이에 활용하는 프로젝트**를 목표로 한다.

아이디어는 크게 **종합 프로젝트**와 **단일 프로젝트**로 구분한다.

- **종합 프로젝트**: 게임 자체의 완성도와 서버·IoT·클라이언트 기술을 종합적으로 보여주는 프로젝트
- **단일 프로젝트**: 하나의 핵심 IoT 인터랙션에 집중하여 체험의 완성도를 높이는 프로젝트

# 1. 종합 프로젝트

## 1-1. IoT 미니게임 오픈월드

### 한 줄 소개

**여러 플레이어가 하나의 월드에서 만나고, IoT 장치를 활용한 다양한 미니게임을 함께 즐기는 멀티플레이 파티 게임**

### 게임 컨셉

플레이어들은 하나의 오픈월드형 로비에 접속하여 자유롭게 돌아다닐 수 있다.

월드 곳곳에는 다양한 미니게임이 존재하며, 플레이어가 원하는 게임을 선택하거나 다른 플레이어들과 파티를 구성하여 참가한다.

미니게임은 단순한 키보드·마우스 조작이 아니라 **카메라, IMU, 근전도 센서, 모터, 낚싯대 등 실제 IoT 장치와 연동**하는 것을 핵심 특징으로 한다.

예시 미니게임:

- 실제 낚싯대를 사용하는 낚시 게임
- 팔이나 몸의 움직임을 인식하는 Fruit Ninja
- 근전도 센서를 이용한 힘겨루기
- IMU를 이용한 균형 잡기
- 카메라 기반 포즈 인식 게임

### 멀티플레이 구조

메인 월드는 Dedicated Server를 통해 여러 사용자가 동시에 접속할 수 있도록 구성한다.

플레이어가 미니게임에 참가하면 별도의 게임 세션을 생성하고 해당 서버로 이동시킨다.

```
Main World
Dedicated Server
       │
       ├── Mini Game Server #1
       │      └─ 낚시
       │
       ├── Mini Game Server #2
       │      └─ Fruit Ninja
       │
       └── Mini Game Server #3
              └─ 힘겨루기
```

미니게임 종료 후 결과를 메인 서버에 전달하고 플레이어는 다시 메인 월드로 복귀한다.

### 예상 역할 분배

**게임 서버 개발자 - 1명**

- 메인 월드 Dedicated Server 구축
- 플레이어 세션 및 상태 관리
- 미니게임 서버 생성/종료
- 메인 서버 ↔ 미니게임 서버 이동 처리
- 게임 결과 및 기록 관리
- Docker 기반 서버 컨테이너화
- Kubernetes 등을 활용한 서버 관리 실험
- Prometheus/Grafana 등을 활용한 서버 모니터링 및 부하 분석

**게임 클라이언트 개발자 - 2명**

- 캐릭터 이동 및 상호작용
- 멀티플레이 동기화
- UI/UX
- 월드 및 게임 플레이 구현
- 미니게임 진입/종료 연출
- IoT 데이터와 게임 로직 연결

**IoT 개발자 - 3명**

- 미니게임별 IoT 장치 설계
- 센서 데이터 수집
- MCU 및 통신 구현
- 모터/액추에이터 제어
- 게임 ↔ IoT 장치 통신
- 실제 플레이를 위한 하드웨어 제작

### 핵심 기술 포인트

`멀티플레이 서버 + 서버 인프라 + 게임 클라이언트 + IoT`를 모두 포함할 수 있다는 것이 가장 큰 특징이다.

특히 여러 종류의 IoT 기술을 각각 하나의 미니게임으로 분리할 수 있어 **팀원별 역할 분담이 비교적 명확하다.**

### 7주 프로젝트 범위

오픈월드 자체를 크게 만드는 것보다는 작은 허브 월드를 제작하고 **완성도 높은 IoT 미니게임 2~3개**를 구현하는 것을 목표로 한다.

## 1-2. IoT 해양 방탈출 협동 게임

### 한 줄 소개

**침몰 위기에 처한 선박 또는 잠수정에서 실제 IoT 장치를 조작하며 탈출하는 멀티플레이 협동 게임**

### 게임 컨셉

플레이어들은 사고가 발생한 선박 또는 잠수정의 승무원이 된다.

목표는 제한 시간 동안 선박에서 발생하는 여러 문제를 해결하고 안전하게 목적지까지 도착하는 것이다.

게임 구조는 **Among Us / Lockdown Protocol / Goose Goose Duck의 Task 수행 구조**를 참고하되, 사회적 추리보다는 **협동과 실제 장치 조작**에 집중한다.

### 플레이 예시

항해 중 무작위로 문제가 발생한다.

```
⚠ 엔진 과열
⚠ 선체 침수
⚠ 통신 장비 고장
⚠ 전력 부족
⚠ 항법 장치 이상
```

플레이어들은 각 구역으로 이동하여 문제를 해결한다.

일부 문제는 게임 내 버튼을 누르는 것이 아니라 실제 IoT 장치를 사용해야 한다.

예를 들어:

- 밸브를 실제로 돌려 압력 조절
- 레버를 움직여 엔진 출력 조절
- 여러 스위치를 순서대로 조작
- IMU 장치를 이용해 균형 유지
- 펌프 장치를 움직여 침수 제거
- 무전기 형태의 장치로 다른 플레이어와 협력

여러 작업이 동시에 발생하기 때문에 플레이어 간 역할 분담과 의사소통이 중요하다.

### 핵심 재미

게임 화면에서 발생한 사건이 **현실의 장치 조작으로 연결되는 것**이 핵심이다.

```
게임
"엔진 압력이 너무 높습니다!"
        ↓
실제 IoT 밸브 조작
        ↓
센서 데이터 전송
        ↓
게임 속 압력 감소
        ↓
위기 해결
```

### 핵심 기술 포인트

- 멀티플레이 협동 게임
- 실시간 게임 상태 동기화
- 다양한 센서 입력
- 물리적 컨트롤러 제작
- 게임 ↔ IoT 양방향 통신
- 여러 IoT 장치를 하나의 게임 시스템으로 통합

### 7주 프로젝트 범위

선박 전체를 크게 구현하기보다는 **3~4개의 공간 + 3~5개의 IoT Task** 정도를 제작한다.

스토리와 공간을 제한하는 대신 실제 장치를 조작했을 때 게임 속 시스템이 반응하는 경험을 완성도 있게 구현하는 것을 목표로 한다.

## 1-3. IoT 전차 / 함정 시뮬레이터

### 한 줄 소개

**실제 조종석을 축소 구현하여 전차 또는 함정을 직접 운용하는 체험형 시뮬레이션 게임**

### 게임 컨셉

전차 또는 함정의 조작 장치를 실제 하드웨어로 구현하고 게임과 연결한다.

단순히 조이스틱 하나로 모든 것을 조작하는 것이 아니라 여러 장치를 실제 역할에 맞게 배치한다.

### 전차 예시

- 조종수 → 차량 이동
- 포수 → 포탑 회전 및 조준
- 장전수 → 장전 장치 조작
- 전차장 → 목표 확인 및 명령

### 함정 예시

- 조타 → 방향 제어
- 엔진 → 출력 조절
- 레이더 → 적 탐지
- 무장 → 포/미사일 조작

각 플레이어가 서로 다른 장치를 담당하는 **협동 시뮬레이터** 형태로 발전시킬 수도 있다.

### 구현 방향

두 가지 방향을 고려할 수 있다.

**A. 기존 게임 연동**

기존 전차/함정 게임의 입력을 IoT 장치와 연결하여 실제 조종석처럼 플레이한다.

**B. 자체 게임 제작**

간단한 전차 또는 함정 게임을 직접 제작하고 IoT 장치를 게임 시스템과 직접 연결한다.

SSAFY 프로젝트에서는 기술적 완성도와 자체 구현 범위를 보여주기 위해 **B 방향을 우선 고려한다.**

### 핵심 기술 포인트

- 다양한 물리 입력 장치
- 센서 및 스위치 처리
- 모터/진동 등을 통한 햅틱 피드백
- 게임 ↔ IoT 실시간 통신
- 멀티플레이 역할 분담
- 실제 조종석을 모사한 하드웨어 설계

# 2. 단일 프로젝트

## 2-1. IoT 무쌍 액션 게임

### 한 줄 소개

**사용자가 실제로 팔을 움직이고 힘을 쓰면서 수많은 적을 쓰러뜨리는 체감형 액션 게임**

### 게임 컨셉

사용자의 팔 또는 무기에 센서를 장착하여 움직임을 인식한다.

사용자가 실제로 휘두르는 행동을 하면 게임 캐릭터가 공격한다.

여기에 모터 또는 저항 장치를 결합하여 공격이나 적과의 충돌 상황에서 **실제 팔에 물리적인 피드백**을 제공한다.

### 주요 기능

- IMU 등을 활용한 팔 움직임 인식
- 공격 방향 및 속도 판정
- 공격 강도 판정
- 다수의 적을 상대하는 액션 게임
- 모터를 이용한 물리적 피드백

### 핵심 재미

단순 모션 인식을 넘어,

**게임에서 무언가를 베거나 막았을 때 현실에서도 반응을 느낄 수 있도록 만드는 것**을 목표로 한다.

## 2-2. IoT 낚시 게임

### 한 줄 소개

**실제 낚싯대를 조작하고 물고기의 저항까지 느낄 수 있는 체감형 낚시 게임**

### 게임 컨셉

실제 낚싯대 형태의 컨트롤러를 제작한다.

사용자가 낚싯대를 던지고 물고기가 미끼를 물면 게임과 연결된 모터가 줄에 힘을 가한다.

물고기의 종류와 행동에 따라 서로 다른 힘과 패턴으로 줄을 당긴다.

### 플레이 흐름

```
낚싯대 캐스팅
     ↓
물고기 탐색
     ↓
입질 발생
     ↓
모터가 줄을 당김
     ↓
사용자가 릴 조작
     ↓
물고기와 힘겨루기
     ↓
낚시 성공 / 실패
```

### IoT 요소

- 낚싯대 움직임 감지
- 릴 회전량 측정
- 모터를 이용한 줄 장력 제어
- 물고기 행동에 따른 저항 패턴
- 진동 등을 이용한 입질 표현

### 핵심 기술 포인트

가장 중요한 부분은 **물고기의 움직임을 모터의 물리적 힘으로 얼마나 자연스럽게 표현할 수 있는가**이다.

IoT 기술 하나에 집중하기 때문에 7주 동안 하드웨어와 게임의 완성도를 높이기 유리하다.

## 2-3. IoT Fruit Ninja

### 한 줄 소개

**실제 검 형태의 컨트롤러를 휘둘러 화면 속 과일을 베는 체감형 Fruit Ninja 게임**

### 게임 컨셉

Fruit Ninja와 Beat Saber의 플레이 방식을 결합한다.

사용자가 실제 검 형태의 IoT 컨트롤러를 들고 화면 앞에서 움직인다.

센서를 통해 검의 위치와 움직임을 추정하고, 화면 속 과일과 충돌했는지를 판단한다.

### 게임 요소

- 과일 방향에 맞춰 베기
- 연속 콤보
- 특정 방향 베기
- 폭탄 회피
- 속도 증가
- 정확도 점수

### IoT 요소

- IMU 기반 움직임 측정
- 카메라 기반 위치 추정
- IMU + Vision Sensor Fusion
- 진동 모터를 이용한 타격 피드백

### 핵심 기술 포인트

단순히 "휘둘렀다"를 인식하는 수준을 넘어 **실제 검의 궤적과 게임 속 검의 움직임을 얼마나 정확하게 일치시킬 수 있는가**가 핵심 기술 과제가 된다.

# 프로젝트 선정 시 고려할 기준

7주 프로젝트라는 점을 고려하여 다음 기준으로 각 아이디어를 평가한다.

1. **시연 임팩트** — 처음 보는 사람이 짧은 시간 안에 재미와 기술을 이해할 수 있는가?
2. **IoT 당위성** — IoT를 억지로 붙인 것이 아니라 IoT가 있어야 재미있는 프로젝트인가?
3. **기술적 깊이** — 단순 센서 입력을 넘어 해결할 만한 기술적 문제가 존재하는가?

5. **7주 완성 가능성** — 핵심 기능을 구현하고 안정화할 시간이 충분한가?
6. **게임 완성도** — 기술 데모에서 끝나지 않고 실제 게임처럼 느껴질 수 있는가?
