# 로비가 무거운 원인 찾기 — 측정 절차

개발 빌드의 `F9` 성능 조절판으로 항목을 하나씩 켜고 끄며 **프레임 시간(ms)** 을 비교한다.

## 왜 ms 인가

GPU 사용률로 보면 안 된다. **100% 에 붙어 버리면 더 나빠져도 100%, 조금 좋아져도 100%** 라
개선이 보이지 않는다. 지금 로비가 정확히 그 상태다.

```
2880×1800 전체화면   GPU 99%   45fps   →  한 프레임 22.2 ms
1920×1080 전체화면   GPU 50%   60fps   →  한 프레임 16.7 ms
```

한 프레임에 몇 ms 드는지가 진짜 값이고, 항목별로 몇 ms 를 아꼈는지가 판단 근거다.

## 준비

1. `Builds/FlowClient/AraAtti-Flow.exe` 를 EC2 인자로 실행한다.
   ```
   AraAtti-Flow.exe -api http://43.202.67.137:5080 -appver prod -region kr
   ```
2. 로비에 들어가 **풀이 많이 보이는 쪽**을 보고 선다.
3. `F9` — 조절판을 연다. **창이 열려 있어야 숫자키가 먹는다.**
4. `F8` — **무제한**을 고른다.
   60 으로 묶여 있으면 무엇을 바꾸든 16.7 ms 가 나와 차이가 안 보인다.
5. `0` — 기준값을 잡는다.

⚠ **측정 내내 움직이지 않는다.** 서 있는 자리와 보는 방향이 달라지면 숫자가 뒤집힌다.
   실제로 컬링을 껐는데 GPU 가 더 낮게 나온 적이 있다. 시점이 달랐기 때문이다.

## 한 항목씩

키를 누르면 **1초 쉬었다가 3초 재서** 한 줄이 쌓인다. 쌓인 뒤 **같은 키를 다시 눌러
원복**하고 다음 항목으로 간다. 두 개를 한꺼번에 바꾸면 어느 쪽이 효과인지 모른다.

| 키 | 항목 | 무엇을 의심하는가 |
|---|---|---|
| `1` | SSAO | 전체 해상도 + DepthNormals 소스 + 고품질 블러로 잡혀 있다 |
| `2` | 그림자 품질 | High 는 픽셀당 7×7 = 49 샘플. Unity 문서도 "Low performance" 라 적었다 |
| `3` | 그림자 캐스케이드 | 4단. 그림자 맵을 네 번 그린다 |
| `4` | 불투명 화면 복사 | 켜져 있다. **끄고 물을 봐라.** 물이 깨지면 물이 쓰고 있다는 뜻 |
| `5` | 깊이 텍스처 | 켜져 있다. 물·SSAO 가 같이 쓸 수 있다 |
| `6` | 후처리 전체 | Bloom·외곽선·안개 등이 실제로 얼마나 드는지 |
| `7` | RenderScale | 1.0 → 0.8 → 0.67 → 0.5 |
| `8` | 업스케일러 | Auto(사실상 Bilinear) → Linear → FSR → STP |
| `9` | 물 숨기기 | 수면이 화면을 크게 차지한다 |
| `F10` | 풀 컬링 | 어제 넣은 60m 거리 컬링 |

## 읽는 법

```
  기준값              22.2 ms  (최악  31.4)
  SSAO 끔             18.1 ms  (최악  25.2)   -4.1 ms     ← 크다. 주범 후보
  그림자 Medium       21.0 ms  (최악  29.8)   -1.2 ms     ← 중간
  불투명복사 끔       22.0 ms  (최악  30.9)   -0.2 ms     ← 거의 없다
```

**-1 ms 미만은 무시해도 된다.** 측정 흔들림과 구분이 안 된다.
같은 항목을 두 번 재서 값이 비슷한지 확인하면 더 믿을 만하다.

ms 와 함께 **화면도 봐라.** 4 ms 를 아꼈는데 물이 깨지면 못 쓰는 설정이다.
로우폴리 만화풍이라 SSAO 처럼 눈에 안 띄는 것도 있다. 스크린샷을 켜고 끈 상태로 찍어 비교한다.

## 그 다음

이 표로 **순위만** 나온다. "SSAO 가 4 ms" 까지는 알아도 "그 안에서 어느 패스가 비싼지" 는
모른다. 그건 에디터의 **Frame Debugger**(Window > Analysis > Frame Debugger) 와
**GPU Profiler** 로 봐야 한다. 다만 먼저 여기서 범인을 좁히고 들어가야 한다.
안 그러면 볼 것이 너무 많다.

## 아직 안 잰 것 — 접속 순간

**전체화면이 무거운 것**과 **사람이 들어올 때 모두 멈추는 것**은 다른 문제다.

```
전체화면이 무겁다      매 프레임 드는 비용        렌더링
사람이 들어와 멈춘다    한 번에 몰리는 비용        외형 생성 · 스키닝 · 텍스처 업로드
```

렌더링을 고쳐도 뒤쪽은 남는다. 그건 프레임 시간이 33 ms 를 넘는 순간을 파일로 남겨서,
스폰 직후 몇 프레임이 얼마나 튀는지 따로 봐야 한다.

## 지금까지 확인된 사실

측정 전에 **파일을 읽어서** 알아낸 것들이다. 원인으로 확정된 것은 아니고 후보다.

```
SSAO                켜짐 · Downsample 꺼짐(전체 해상도) · Source DepthNormals · 블러 High
그림자              Soft Shadow High(7×7) · 캐스케이드 4 · 2048 · 거리 50
조명                Directional 1(그림자 켬) + Point 5(그림자 전부 끔) · 추가광원 PerPixel
화면 복사           깊이 켬 · 불투명 켬(절반 해상도)
MSAA                꺼짐
RenderScale         1.0 · 업스케일러 Auto(정수배율 아니면 Bilinear)
오클루전 컬링        안 구움  (m_OcclusionCullingData: {fileID: 0})
라이트맵            안 구움  (m_LightingDataAsset: {fileID: 0})
라이트맵 UV         모델 233개 중 3개만 켜짐 → 지금 굽자면 230개 재임포트부터
LOD                 정글 프리팹 202개 중 60개에만 LODGroup
                    Foliage 로 바꾼 94개 중 40개
```

⚠ **프리팹에 LODGroup 이 있다고 실제로 잘 바뀌는 것은 아니다.** 마찬가지로 Volume Profile 에
효과 이름이 있다고 다 도는 것도 아니다. 조절판 위쪽이 **런타임 실제 값**을 읽어서 보여 주니
그쪽을 믿어라.
