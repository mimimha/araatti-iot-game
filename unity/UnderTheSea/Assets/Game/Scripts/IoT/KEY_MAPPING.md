# 키 매핑 — 로비 · 낚시 · 미니게임별

완드(양손 2대)와 키보드에서 **어느 버튼이 어떤 행동인지**만 정리한 표입니다.
왜 이렇게 됐는지는 [IotPlayerController.md](IotPlayerController.md) 를 봅니다.

## 완드 1대의 구성

| 부품 | 코드에서 부르는 이름 | 펌웨어 |
|---|---|---|
| 조이스틱 | `Stick` (왼손 = `Move`, 오른손 = `Look`) | `PIN_JOY_X/Y` |
| 버튼 1 | `Button1` | `PIN_BTN1` (GPIO 4) |
| 버튼 2 | `Button2` | `PIN_BTN2` (GPIO 5) |
| IMU 기울기 (roll) | `Tilt` | |
| IMU 비틀기 (yaw) | `Rotation` | |
| IMU 동작 | `HorizontalSwing` 가로 휘두르기 · `VerticalSwing` 내리치기 · `Thrust` 찌르기 | |

- 완드는 행동 이름을 모릅니다. 위 값만 내보내고, **각 게임이 자기 행동으로 해석**합니다.
- 키보드는 `KeyboardPlayerController` 가 **부품 하나에 키 하나**로 흉내냅니다. 키보드에서 되는 것은 완드에서도 그대로 됩니다.
- 완드가 하나도 안 붙어 있으면 `IotPlayerController` 가 키보드로 자동 전환합니다.

## 로비

| 행동 | 완드 | 키보드 |
|---|---|---|
| 이동 | 왼손 스틱 | `W A S D` |
| 카메라 | 오른손 스틱 | 마우스 |
| 점프 | 오른손 버튼 1 (2대일 때만) | `Space` |
| 달리기 | 오른손 버튼 2 (누르고 있기 · 2대일 때만) | `Shift` (누르고 있기) |
| 낚시 시작 | 왼손 버튼 1 | `C` |
| 미니게임 포탈 입장 | 왼손 버튼 1 | `F` |
| 이정표 이동 창 | 왼손 버튼 1 | `F` |
| 제단 | 왼손 버튼 1 | `E` |
| 춤 휠 열기 | 왼손 버튼 2 | `Q` |
| 춤 고르기 | 오른손 스틱으로 가리키고 왼손 버튼 2 | 마우스로 가리키고 좌클릭 · `1`~`5` |
| 튜토리얼 [건너뛰기] | 왼손 버튼 2 ([건너뛰기] 가 화면에 보일 때만 — 그동안 춤 휠은 안 열린다) | 마우스 클릭 |

- 완드는 버튼이 모자라서 낚시 · 포탈 · 이정표 · 제단을 **왼손 버튼 1 하나**로 합쳤습니다. 낚시터가 먼저이고, 나머지는 **내 캐릭터에서 가장 가까운 것**을 고릅니다. 이정표가 포탈 바로 앞에 서 있어서 고정 순서로는 한쪽이 안 눌립니다. (`IotLobbyInteract`)
- 가까이 아무것도 없는데 누르면 콘솔에 `[IotLobbyInteract] 왼손 버튼 1 — 가까이 있는 … 없습니다` 가 찍힙니다. 포탈 앞에서 이 줄이 보이면 포탈의 거리 판정이 거짓인 것입니다.
- 춤 휠은 오른손 스틱으로 가리킨 칸이 스틱을 놓아도 남습니다. 아무 칸도 안 가리키고 왼손 버튼 2 를 누르면 그냥 닫힙니다. 휠이 열린 동안에는 카메라가 돌지 않고 왼손 버튼 1 도 쉽니다.
- 달리기는 예전에 왼손 버튼 2 토글이었습니다. 춤 휠에 자리를 내주고 광산과 같은 오른손 버튼 2 (누르고 있기)로 옮겼습니다. 오른손 엄지는 카메라 스틱을 잠깐 놓아도 걷기가 끊기지 않습니다.
- 낚시하는 동안에는 왼손 버튼 1 · 2 가 아무 일도 하지 않습니다. 낚시터 옆 포탈로 잘못 들어가는 것을 막으려는 것입니다.
- 채팅을 치는 동안에는 완드 입력도 막힙니다.
- 키보드와 완드 입력은 **더해집니다.** 완드를 들고 있어도 키보드로 조작할 수 있습니다.
- 키보드에서는 포탈과 이정표가 둘 다 `F` 라, 둘 다 가까우면 `F` 한 번에 창이 두 개 뜹니다. 완드는 가까운 쪽 하나만 엽니다.

관련 코드: `PlayerInputProvider` (이동·점프·달리기), `LocalPlayerView` (카메라), `IotLobbyInteract` (상호작용 · 춤 휠). 씬에 따로 붙이지 않습니다 — `IotLobbyInstaller` 가 로비에 들어올 때 코드로 붙입니다.

## 선택지 창 (모든 씬 공통)

제단 봉헌 · 이정표 이동 · 인원 선택 · 매칭 판 · 결과 판처럼 **버튼을 골라 누르는 창**이 떠 있는 동안입니다.

| 행동 | 완드 | 키보드 · 마우스 |
|---|---|---|
| 버튼 옮기기 | 왼손 스틱을 튕긴다 (쥐고 있으면 이어서 옮겨 간다) | 마우스 |
| 누르기 | 왼손 버튼 1 | 좌클릭 |
| 닫기 · 취소 | 왼손 버튼 2 | `Esc` · [닫기] · [취소] |

- 강조된 버튼에 **노란 테두리**가 생깁니다. 창이 뜨면 닫기 · 취소가 아닌 첫 버튼에 있습니다.
- 창이 떠 있는 동안 완드로는 캐릭터가 걷지 않고, 왼손 버튼 1 이 포탈 · 이정표를 다시 누르지 않습니다. (인원 선택 창은 이동을 잠그지 않아서 따로 막았습니다)
- 결과 판에는 닫기가 없습니다. [로비로] 를 눌러야 끝납니다.
- 창 파일은 하나도 고치지 않았습니다. 새 창을 추가하려면 `IotUiNavigator.FindOpenScreen` 에 한 줄 넣습니다.

관련 코드: `IotUiNavigator`

## 낚시 (로비 안)

| 행동 | 완드 | 키보드 |
|---|---|---|
| 낚시 시작 | 왼손 버튼 1 (낚시터 근처) | `C` |
| 챔질 (입질이 왔을 때) | 오른손 버튼 2 | `J` |
| 타이밍 릴링 (파이팅 중) | 오른손 버튼 2 | `J` |

- 챔질과 릴링은 버튼 하나를 같이 씁니다. 키보드 `J` 도 마찬가지입니다.
- 지금 낚시(V3)가 실제로 읽는 값은 챔질과 타이밍 둘뿐이라, 완드도 이 둘만 채웁니다. 키보드의 `Space` · `R` · `Q/E` · 방향키는 예전 버전(V2)용이고 지금 낚시에서는 쓰이지 않습니다.
- 낚시하지 않을 때 누른 오른손 버튼 2 는 버립니다. 쌓아 두면 낚시를 시작하자마자 챔질이 터집니다.
- 로비처럼 키보드와 완드가 **더해집니다.** 완드를 들고 있어도 `J` 로 챔질할 수 있습니다.
- **진동** — 챔질이 걸리면 양손이 크게(0.8 · 0.25초), 타이밍 릴링이 PERFECT 면 오른손이 세게(0.7 · 0.12초), GOOD 이면 약하게(0.4 · 0.08초) 웁니다. MISS 는 안 웁니다. 낚시 효과음이 나는 순간과 같습니다.

관련 코드: `IotFishingBridge`, `WandFishingInputSource`

## 배 협동

프로필: `Shared`

| 행동 | 완드 | 키보드 |
|---|---|---|
| 걷기 | 왼손 스틱 | `W A S D` |
| 달리기 | 왼손 버튼 2 (토글) | `Shift` (토글) |
| 도움 요청 | 왼손 버튼 1 | `C` |
| 카메라 (좌우만) | 오른손 스틱 | 마우스 우클릭 드래그 |
| 상호작용 (붙기 · 집기 · 놓기 · 장전) | 오른손 버튼 1 | `Space` |
| 발사 · 망치질 | 오른손 버튼 2 | `K` |
| 망치질 | 오른손 내리치기 (`VerticalSwing`) | `K` |
| 조타 | 양손 기울기 평균 | `J` / `L` |
| 돛 | 양손 비틀기 평균 | `J` / `L` |
| 시작 설명 팝업 닫기 | 오른손 버튼 2 | `Enter` · `Esc` · 그림의 닫기 클릭 |

- 달리기가 토글인 이유: 엄지가 버튼을 누르러 스틱을 떠나면 걷기가 멈추기 때문입니다.
- 조타는 조타륜에 붙는 순간의 손 각도를 중립(0)으로 잡습니다. 그 뒤로 움직인 만큼만 배가 돕니다. (`HelmTask`)

관련 코드: `ShipCoopInput`, `ShipCoopInputProvider`

## 광산

프로필: `Mine`

| 행동 | 완드 | 키보드 |
|---|---|---|
| 이동 | 왼손 스틱 | `W A S D` (방향키는 안 됨) |
| 달리기 | 오른손 버튼 2 (누르고 있기) | `Shift` |
| 땅 파기 | 내리치기 (`VerticalSwing`, 어느 손이든) | `Space` |
| 땅 복구 | 왼손 버튼 1 | `C` |
| 힌트 | 왼손 버튼 2 | `J` |
| 카메라 | — | 마우스 우클릭 드래그 |

- 광산은 왼손 버튼 2 가 힌트라서 달리기를 오른손 버튼 2 로 옮겼습니다. 토글이 아니라 **누르고 있기**입니다.
- 오른손 버튼 1 은 읽지 않습니다. 키보드에서는 `Space` 인데, 광산의 `Space` 는 파기(내리치기)입니다.

관련 코드: `MineDigger`, `MineMoveInput`

## 무쌍

프로필: `Warriors` (씬이 `SetControlProfile` 로 직접 정합니다)

| 행동 | 완드 | 키보드 |
|---|---|---|
| 이동 | 왼손 스틱 | `W A S D` |
| 카메라 | 오른손 스틱 | 마우스 우클릭 드래그 |
| 가로 베기 | 가로 휘두르기 (`HorizontalSwing`) | `J` |
| 세로 베기 | 내리치기 (`VerticalSwing`) | `K` |
| 찌르기 | 찌르기 (`Thrust`) | `L` |

- 공격 방향은 **어느 손인지가 아니라 IMU가 판정한 동작 종류**로 정합니다. 어느 손으로 휘둘러도 됩니다.

관련 코드: `WarriorsKeyboardInput` (이름과 달리 `IPlayerController` 를 읽습니다), `WarriorsThirdPersonCamera`

## 완드를 1대만 들 때

1대면 `Left` 와 `Right` 가 **같은 기기**입니다. 그래서 버튼이 겹치는 행동은 빠집니다.

| 게임 | 빠지는 것 |
|---|---|
| 로비 | 점프 (상호작용과 겹침), 달리기 (춤 휠과 겹침), 카메라 · 춤 고르기 (스틱을 걷기가 씀) |
| 배 협동 | 도움 요청 · 달리기, 카메라 |
| 광산 | 달리기 (힌트 버튼과 겹침) |

키보드에서는 `KeyboardPlayerController` 의 `twoDevices` 를 끄면 1대 상태를 흉내낼 수 있습니다.
