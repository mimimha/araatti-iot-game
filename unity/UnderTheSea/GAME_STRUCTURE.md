# UnderTheSea 게임 구조 규칙

본 문서는 게임의 전체 흐름과 팀원 간 작업 규격을 정의합니다.

`CONVENTION.md`가 **"파일을 어디에 두는가"**에 대한 규칙이라면,
본 문서는 **"각자 만든 것을 어떻게 이어붙이는가"**에 대한 규칙입니다.

작업을 시작하기 전에 본인 담당 부분의 규격을 확인합니다.

---

## 1. 게임 전체 흐름

```text
게임 실행
   │
   ▼
┌──────────────┐
│    Boot      │  초기화 전용. 화면에는 로고만 표시되고 바로 넘어간다.
└──────────────┘
   │
   ▼
┌──────────────┐
│    Title     │  닉네임 입력
└──────────────┘  [방 만들기] / [방 참가하기]
   │
   │  ← 여기서 네트워크 연결이 성립한다
   ▼
┌──────────────┐
│  MainWorld   │  최대 4명이 같은 바다에 모인다.
└──────────────┘  캐릭터 이동이 서로에게 보인다.
   │
   │  ← 미니게임 입구에 들어가면
   ▼
┌──────────────┐
│  MiniGame    │  무쌍 / 배 협동 / 광산
└──────────────┘
   │
   │  ← 끝나면 결과를 들고
   ▼
  MainWorld 복귀
```

### 별도의 Lobby 씬을 만들지 않습니다

방 만들기와 참가는 `Title` 씬 안에서 처리합니다.

씬을 하나 줄여서 구조를 단순하게 유지하기 위함입니다.

## 2. 네트워크 방식

### 결정 사항

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 라이브러리 | **Netcode for GameObjects (NGO)** | Unity 공식 패키지. Unity 6.5와 호환 문제가 없음 |
| 서버 형태 | **호스트 방식** | 방을 만든 사람이 서버 역할을 겸한다. 별도 서버를 만들 필요가 없음 |
| 연결 방식 | **같은 공유기 안에서 IP 직접 연결** | 인터넷 중계 서비스 설정 없이 바로 시작 가능 |
| 최대 인원 | **4명** | 시연 기준 |

### 용어

| 용어 | 뜻 |
| --- | --- |
| **호스트 (Host)** | 플레이어 중 한 명의 컴퓨터가 심판 역할까지 같이 하는 것 |
| **클라이언트 (Client)** | 호스트에 접속하는 나머지 플레이어 |
| **동기화** | 내 화면의 움직임이 다른 사람 화면에도 보이게 하는 것 |
| **스폰 (Spawn)** | 플레이어가 접속할 때 캐릭터가 생성되는 것 |

### 연결 흐름

```text
민화 컴퓨터           서연 컴퓨터
[방 만들기]  ←────    [방 참가하기]
 (호스트)              (클라이언트)
                              효진 컴퓨터
                       ←────  [방 참가하기]
```

호스트가 게임을 끄면 방이 사라집니다. 시연 중에는 호스트를 담당한 사람이 게임을 끄지 않습니다.

### 주의 — 시연 환경 확인 필요

교육장 공용 와이파이는 **같은 와이파이에 있어도 컴퓨터끼리 직접 통신이 막혀 있는 경우**가 있습니다.

시연 전에 반드시 실제 환경에서 4대 접속을 테스트합니다.

막혀 있다면 다음 중 하나로 해결합니다.

- 공유기를 직접 하나 가져와서 연결
- 노트북 한 대의 핫스팟에 나머지가 접속
- Unity Relay(인터넷 중계 서비스)를 추가로 붙임

**Relay는 처음부터 붙이지 않습니다.** 위 방법으로 안 될 때만 추가합니다.

## 3. 씬 목록과 담당자

씬 이름은 아래로 확정합니다. **임의로 변경하지 않습니다.**

```text
Assets/Game/Scenes/Main/
├── CoreGames/
│   ├── Boot.unity        (민화)
│   ├── Title.unity       (민화)
│   └── MainWorld.unity   (효진)
└── MiniGames/
    ├── Warriors.unity    (서연)  무쌍
    ├── ShipCoop.unity    (민화)  배 협동
    └── Mine.unity        (효진)  광산
```

### 씬 규칙

- 새 씬을 만들면 반드시 `File > Build Settings`에 등록합니다. 등록하지 않으면 씬 전환이 되지 않습니다.
- 씬 전환 코드는 민화가 관리합니다. 각자 씬에서 `SceneManager.LoadScene`을 직접 호출하지 않습니다.
- 담당하지 않은 씬은 열어보는 것은 괜찮지만 저장하지 않습니다.

## 4. 캐릭터 프리팹 규격 — 담당: 서연

### 위치

```text
Assets/Game/Prefabs/Characters/Player.prefab
```

### 반드시 지켜야 할 것

**1) 씬에 캐릭터를 미리 배치하지 않습니다.**

멀티플레이에서 캐릭터는 플레이어가 접속하는 순간 생성됩니다.
씬에 미리 놓아둔 캐릭터는 사용되지 않습니다.

**2) 프리팹의 맨 위 오브젝트는 빈 오브젝트로 만듭니다.**

```text
Player               ← 빈 오브젝트 (여기에 스크립트가 붙습니다)
├── Model            ← 실제 캐릭터 모델
│   └── (본, 파츠 등)
└── (기타)
```

모델을 바로 맨 위에 두면 나중에 스크립트를 붙일 때 회전 축이 어긋납니다.

**3) 이동 스크립트는 넣지 않습니다.**

서연이 담당하는 것은 **모델, 애니메이션, 프리팹 구조**까지입니다.

이동과 네트워크 관련 스크립트는 민화가 붙입니다.
멀티플레이에서는 이동을 아무 곳에서나 처리하면 다른 사람 화면과 어긋나기 때문입니다.

**4) 애니메이터 파라미터 이름을 아래로 맞춥니다.**

| 이름 | 타입 | 뜻 |
| --- | --- | --- |
| `Speed` | Float | 이동 속도. 0이면 정지, 클수록 빠르게 |
| `IsGrounded` | Bool | 땅에 닿아 있는지 |

민화가 코드에서 이 이름으로 값을 넣습니다. 이름이 다르면 애니메이션이 동작하지 않습니다.

필요한 파라미터가 더 생기면 민화와 상의 후 이 표에 추가합니다.

## 5. MainWorld 씬 규격 — 담당: 효진

### 반드시 포함해야 할 것

**1) 플레이어 시작 위치 4개**

```text
Hierarchy
└── SpawnPoints          ← 빈 오브젝트
    ├── SpawnPoint_1     ← 빈 오브젝트
    ├── SpawnPoint_2
    ├── SpawnPoint_3
    └── SpawnPoint_4
```

접속한 순서대로 이 위치에 캐릭터가 생성됩니다.
서로 겹치지 않게 2~3미터씩 떨어뜨립니다.

**2) 미니게임 입구 3개**

```text
Hierarchy
└── Entrances
    ├── Entrance_Warriors    ← 무쌍
    ├── Entrance_ShipCoop    ← 배 협동
    └── Entrance_Mine        ← 광산
```

각 입구 오브젝트에는 **Collider를 붙이고 `Is Trigger`를 체크**합니다.
캐릭터가 이 영역에 들어오면 미니게임으로 진입합니다.

보기 좋게 문이나 표지판 모델을 붙이는 것은 자유입니다.

**3) 바닥에 Collider**

바닥에 Collider가 없으면 캐릭터가 아래로 떨어집니다.

### 하지 않아야 할 것

- 씬에 캐릭터를 배치하지 않습니다 (접속할 때 생성됨)
- 오브젝트 이름을 위 규격과 다르게 짓지 않습니다 (코드가 이 이름으로 찾습니다)

### 자유롭게 해도 되는 것

조명, 지형, 물, 후처리, 장식물, 스카이박스 등 보이는 것은 모두 자유입니다.

## 6. 미니게임 규격

### 현재 상태 — 추후 확정

미니게임의 상세 규격은 **MainWorld가 완성된 이후에 확정**합니다.

**그전까지 미니게임 제작을 시작하지 않습니다.**
규격 없이 각자 만들면 나중에 합칠 때 전부 다시 만들어야 합니다.

### 지금 확정된 것 (이것만 지키면 됩니다)

미니게임은 끝날 때 아래 두 가지를 반드시 돌려줍니다.

```text
성공 / 실패     (예 / 아니오)
점수            (숫자)
```

미니게임을 어떻게 만들든 이 두 가지만 나오면 MainWorld에 연결할 수 있습니다.

## 7. 스크립트 폴더 구조

```text
Assets/Game/Scripts/
├── Core/             씬 전환, 게임 상태 관리        (민화)
├── Network/          접속, 방 만들기/참가, 동기화   (민화)
├── Character/        캐릭터 이동, 애니메이션 연결   (민화)
├── UI/               화면 버튼 처리                 (민화)
└── MiniGames/
    ├── Warriors/                                    (서연)
    ├── ShipCoop/                                    (민화)
    └── Mine/                                        (효진)
```

본인 담당 폴더 밖의 스크립트는 수정하지 않습니다.
수정이 필요하면 담당자에게 요청합니다.

## 8. 외부 에셋과 Git 용량 관리

에셋 스토어에서 에셋을 구매해서 사용할 예정입니다.
에셋 파일은 용량이 크기 때문에 아래 규칙을 지킵니다.

### 에셋을 Import 하기 전에

**반드시 팀에 먼저 공유합니다.**

- 어떤 에셋인지
- 용량이 얼마인지

수백 MB짜리 에셋을 여러 명이 각자 Import 하면 저장소 용량이 금방 초과됩니다.

### 큰 파일은 Git LFS로 관리합니다

`.psd`, `.fbx`, `.wav`, 큰 텍스처 등은 Git LFS(대용량 파일 전용 저장 방식)로 관리합니다.

**에셋을 처음 Import 하기 전에 설정해야 합니다.**
에셋이 들어온 뒤에 설정하면 저장소 기록을 전부 다시 만들어야 합니다.

> SSAFY GitLab에서 LFS 사용이 가능한지 확인이 필요합니다. (담당: 민화)

### Import 후 확인

```bash
git status
```

의도하지 않은 파일이 포함되지 않았는지 확인합니다.

## 9. 이번 프로젝트에서 하지 않는 것

초기 기획안(`README.md`)에는 아래 내용이 있으나, 7주 일정과 인원 구성상 **범위에서 제외**합니다.

| 기획안 내용 | 실제 진행 방식 |
| --- | --- |
| Dedicated Server 직접 구축 | **호스트 방식**으로 대체 |
| 미니게임마다 서버 분리 | **같은 방 안에서 씬만 전환** |
| Docker / Kubernetes | 하지 않음 |
| Prometheus / Grafana 모니터링 | 하지 않음 |
| 로그인 / 회원가입 | **닉네임 입력만** |

서버 전담 인원이 없기 때문입니다.
여유가 생기면 그때 다시 논의합니다.

## 10. 진행 순서

MainWorld를 먼저 완성한 뒤 미니게임으로 넘어갑니다.

```text
1단계   큐브 하나가 두 창에서 서로 보이고 움직인다        (민화)
          ↓
2단계   4명까지 접속되는 것을 확인한다                    (민화)
          ↓
3단계   Boot → Title → MainWorld 흐름을 연결한다          (민화)
          ↓
4단계   큐브를 서연의 캐릭터로 교체한다                   (민화 + 서연)
          ↓
5단계   빈 바닥을 효진의 맵으로 교체한다                  (민화 + 효진)
          ↓
6단계   미니게임 규격을 확정한다                          (전체 회의)
          ↓
7단계   각자 미니게임을 만든다                            (전체)
          ↓
8단계   IoT 장치를 연결한다                               (전체)
```

### 중요

민화는 **캐릭터와 맵이 완성되기를 기다리지 않습니다.**

큐브와 빈 바닥으로 먼저 전부 동작하게 만들고, 나중에 진짜 캐릭터와 맵으로 교체합니다.
그래야 세 사람이 서로를 기다리지 않고 동시에 작업할 수 있습니다.

# 핵심 규칙 요약

1. 씬 이름은 본 문서의 목록으로 고정합니다.
2. 캐릭터는 씬에 미리 배치하지 않습니다. 접속할 때 생성됩니다.
3. 캐릭터 프리팹의 맨 위는 빈 오브젝트로 만듭니다.
4. 애니메이터 파라미터 이름은 `Speed`, `IsGrounded`로 맞춥니다.
5. MainWorld에는 `SpawnPoint_1~4`와 `Entrance_*`를 규격대로 배치합니다.
6. 미니게임은 규격이 확정되기 전까지 시작하지 않습니다.
7. 미니게임은 끝날 때 성공/실패와 점수를 돌려줍니다.
8. 씬 전환은 민화가 관리합니다. 각자 씬에서 직접 호출하지 않습니다.
9. 에셋을 Import 하기 전에 팀에 먼저 공유합니다.
10. 민화는 큐브와 빈 바닥으로 먼저 만들고 나중에 교체합니다.
